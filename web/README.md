# 달바 레딧 모니터 — 웹사이트 (Vercel)

`reddit-dalba-monitor` 가 모은 레딧 언급을 보는 화면입니다.
필터·검색·일별 추이가 있고, 휴대폰에서도 볼 수 있습니다.

## 어떻게 굴러가나

```
GitHub Actions (매일 9시, 시간 제한 없음)
   └─ 레딧 수집 (4~6분)
        └─ web/data/mentions.json 갱신 → 커밋 → 푸시
             └─ Vercel 이 감지해서 자동 재배포
```

수집을 Vercel Cron 안에서 돌리지 않는 이유는 **Hobby 플랜 함수 실행 시간이 최대
60초**라서입니다. 수집은 레딧 분당 100회 제한을 지키느라 몇 분이 걸리므로 타임아웃으로
죽습니다. 그래서 오래 걸리는 수집은 Actions 가 하고, Vercel 은 결과를 보여주기만 합니다.

DB 는 쓰지 않습니다. 데이터가 JSON 파일 하나라 추가 비용·설정이 없고, git 에 이력도 남습니다.

## Vercel 배포 (처음 한 번만)

1. <https://vercel.com/new> 에서 이 리포지토리를 import 합니다.
2. **Root Directory 를 `web` 으로 지정합니다.** ← 이것만 놓치지 마세요.
   (프레임워크는 Next.js 로 자동 인식됩니다)
3. **Environment Variables** 에 비밀번호를 추가합니다.

   | 이름 | 값 | 설명 |
   | --- | --- | --- |
   | `SITE_PASSWORD` | 원하는 비밀번호 | 사이트를 열 때 물어봅니다 |

   Vercel 주소는 아무나 접근할 수 있으므로 **설정을 권장합니다.**
   설정하면 접속 시 브라우저 기본 로그인 창이 뜨고, **아이디는 아무거나** 넣고
   비밀번호만 맞으면 들어갑니다. 설정하지 않으면 주소를 아는 사람은 누구나 볼 수 있습니다.
4. Deploy 를 누르면 끝입니다. 이후 데이터가 갱신될 때마다 자동으로 다시 배포됩니다.

## 화면 구성

- **필터 한 줄** — 기간(7/30/90일·전체) · 종류 · 관련도 · 서브레딧 · 검색어.
  필터는 아래의 통계·차트·목록을 **모두 같은 기준으로** 좁힙니다.
- **통계 타일** — 현재 조건에서의 언급 수 / 관련 / 확인필요 / 서브레딧 수
- **일별 언급 수** — 막대에 마우스를 올리면(또는 키보드 포커스) 날짜별 건수가 나옵니다
- **언급 목록** — 최신순. 브랜드명은 본문에서 강조 표시되고, 원문 링크로 바로 갈 수 있습니다

날짜 기준은 **마지막 수집 시각**입니다. 수집이 멈추면 화면도 그 시점을 정직하게 가리킵니다.

## 로컬에서 보기

```bash
cd web
npm install
npm run dev     # http://localhost:3000
```

데이터가 비어 있으면 안내 화면이 나옵니다. 수집기를 한 번 돌리거나
`data/mentions.json` 에 샘플을 넣어 보세요.

## 참고

- 다크 모드는 OS 설정을 따라갑니다(라이트/다크 각각 별도 검증한 색을 씁니다).
- 검색엔진에는 노출되지 않도록 `noindex` 를 걸어 두었습니다.
- 보관 건수는 수집기의 `MAX_ROWS`(기본 5000)로 조절합니다. 오래된 항목부터 정리됩니다.
