# Live GMV 집계

틱톡샵 제품별 라이브 유입매출을 pid 단위로 합산한다.

`매출지표 (슬랙, 주간보고)` 시트의 제품별 유입매출 RAW 탭을 읽어
제품마다 **셀러 라이브 + 크리에이터 라이브** 매출을 더하고,
그 결과만 담은 작은 스프레드시트를 따로 만든다.

## 왜 이렇게 도나

**원본 시트가 4MB를 넘는다.** 그래서 Drive 커넥터가 통째로 내보내지 못한다
(`File too large for export`). 결과만 담은 작은 시트를 하나 만들어 두면
그건 바로 읽힌다.

**이 저장소는 공개다.** Actions 로그를 누구나 읽을 수 있으므로
매출 숫자는 로그에 남기지 않는다. 시트에만 쓰고, 로그에는
몇 행을 읽었는지와 결과 시트 주소만 남긴다. 주소는 비밀이 아니다 —
열려면 공유 권한이 있어야 한다.

## 어떤 열을 읽나

| 열 | 헤더 | |
|---|---|---|
| A | (헤더 없음) 날짜 | |
| B | Product Name | |
| C | Product ID | pid |
| **G** | **Seller LIVE-attributed GMV** | 셀러 라이브 (직접+간접) |
| **N** | **Creator LIVE-attributed GMV** | 크리에이터 라이브 (직접+간접) |

바로 옆에 이름이 비슷한 열이 하나씩 더 있다 — H `Seller LIVE GMV`,
O `Affiliate LIVE GMV`. 이건 간접을 뺀 **직접** 매출이다.
탭 이름이 '유입매출'이므로 attributed 쪽인 G·N 이 맞다.

열 위치는 고정하지 않고 **헤더 이름으로 찾는다.** 원본에서 열이 밀리면
로그에 경고를 남기고 이름 기준으로 계속 읽는다.

## 돌리는 법

Actions 탭 → **Live GMV 집계** → Run workflow.

| 입력 | |
|---|---|
| `src_sheet_id` | 원본 스프레드시트 ID |
| `src_tab` | 탭 이름. 비우면 이름에 «유입매출» 이 든 탭을 찾는다 |
| `date_from` / `date_to` | `YYYY-MM-DD`. 비우면 전체 기간 |
| `top_n` | 결과에 실을 제품 수 (기본 50) |
| `share_email` | 결과 시트를 공유받을 주소 |

결과 시트에는 탭이 둘 생긴다. **집계** 에는 순위·pid·제품명·셀러·크리에이터·합산·셀러
비중·행 수가, **기준** 에는 원본 탭 이름과 실제 집계 기간, 건너뛴 행 수가 들어간다.
숫자를 믿기 전에 **기준** 탭을 먼저 보면 된다.

## 필요한 것

- Secret `GOOGLE_CREDENTIALS` — 서비스 계정 JSON.
  이 저장소의 다른 워크플로가 쓰는 것과 같다.
- 원본 시트가 그 서비스 계정에 **공유돼 있어야 한다.** 안 돼 있으면
  `SpreadsheetNotFound` 로 떨어진다. 시트에서 서비스 계정 주소를
  뷰어로 추가하면 된다.
